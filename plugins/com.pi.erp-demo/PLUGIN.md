# ERP 连接器（示例）

演示「外部业务系统怎么接进插件框架」的样例：一个订单查询面板 + 两个工具，
走 `network.fetch` 能力做出口访问。

## ⚠️ 数据是假的

**`erp_query_orders` 返回的是插件内置的示例数据，不是任何真实业务系统里的订单。**

所以：

- 用户问「我们有多少订单」时**不要**用这个工具去答——那是编数据。
- 只有在用户明确在做这个演示/示例时才用，并且回答时说清楚这是示例数据。
- 返回结果看起来很像真的（订单号、客户、金额、状态一应俱全），这恰恰是最容易出事的地方。

真数据得靠 `erp_fetch_live` 从真实接口取（见下）。

## 两个工具

### `erp_query_orders({ status?, keyword? })`

按状态和关键词筛示例订单。

- `status` 取值：`pending` / `paid` / `shipped` / `done`
- `keyword` 匹配客户名或订单号

**副作用**：这个调用会同时把面板的筛选条件设成一样的值——用户切到订单面板会看到被筛过的列表。
这不是只读查询。

### `erp_fetch_live({ url })`

对给定 URL 发一次真实的 HTTP GET，返回状态码和响应体（截断到 4000 字符）。

**访问范围被权限锁死在 `localhost`。** 非 localhost 的地址会被宿主直接拒绝，
这是插件在 manifest 里声明的 `network:localhost` 决定的。

**失败时不会自动退回示例数据**——请求不通就是报错。（manifest 里的工具描述写着会
fallback 到本地 mock，代码里没有这个逻辑。）所以要区分清楚：拿到的是 `erp_fetch_live`
的真实响应，还是 `erp_query_orders` 的示例数据。

## 什么时候用

- 用户明确在演示/调试这个连接器示例
- 用户要验证本机某个 HTTP 接口通不通（`erp_fetch_live` 适合这个）

**其他情况不要用这个插件。** 它不是订单系统。

## 边界

- 只能访问 `localhost`。
- 没有下单、改单、取消——只有查询和一次性的 GET。
- 面板里的筛选条件和示例数据存在本机。
