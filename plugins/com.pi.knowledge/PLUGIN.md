# 知识库

存**长期有用**的事实：用户偏好、项目背景、定下来的决定、以后要复用的话术。
和它相对的是对话历史——对话会被压缩、会滚出上下文，知识库不会。

## 三个工具

### `kb_save({ title, content })`

存一条。`title` 用来以后找它，写具体一点（「部署流程」比「笔记」好搜）。

### `kb_search({ query })`

按关键词搜，**不区分大小写、按子串匹配**，标题和正文都算。

不是语义检索——搜「部署」匹配不到只写了「上线流程」的条目。搜不到就换个词再试，
或者用 `kb_list` 看一眼实际存了什么。

### `kb_list()`

列出全部条目。

## 你多半不用主动搜

知识库挂了一个自动注入的上下文（`kb.auto`）：**用户每次发消息前，系统会先检索一遍，
把相关条目拼进你能看到的上下文里**（由插件设置里的「自动注入上下文」控制，默认开）。

所以：

- 用户提到「之前说的那个」，**先看当前上下文里已注入的条目**，别急着 `kb_search`
- 上下文里没有，再去搜
- 搜也搜不到，就老实说没找到，不要编

## 什么时候存

- 用户的稳定偏好（「我习惯用 pnpm」「回复别用 emoji」）
- 项目级的约定和决定（「这个仓库用 pnpm，不用 npm」）
- 用户明确说「记住」

**不要存**：一次性的任务、临时的中间结果、对话里随手一提的东西。
存进去的东西是长期的，塞垃圾会让自动注入的上下文变吵。

## 另外两个入口（用户侧，不用你调）

- 划词菜单里的「存入知识库」——选中一段文字直接存
- 面板里可以手动增删改

## 边界

- 只存本机，不同步、不外发。
- 没有向量检索，只有子串匹配（见上）。
