# 事项

用户的计划表。**待办、日程、定时任务是同一种东西**，区别只在于：没有时间的是待办，有时间的是日程，有时间加重复加触发的就是定时任务。

## 四个工具

### `item_add({ title, when?, end?, note?, repeat?, remindBefore?, onDue? })`

记一条。`title` 必填；给了 `when` 才有时间，否则是一条纯待办。

**`when` 优先用明确写法**（`2026-09-30 14:00`、`2026-09-30`）。也认自由文本（`明天下午3点`、`后天`、`下周五`、`下个月1号`），但那是有损的：**解析结果会原样回给你**，如果读错了用户会看见。

> `后天` 和 `大后天` 这类词标准的解析库其实读不出来，是这里补上的。但 `下周`、`周末` 这种没有具体日子的说法**会被拒绝**——宁可问清楚，也不猜一个日期存下去。

- `repeat`：`daily` / `weekly` / `monthly` / `yearly`，或直接给 RRULE，例如 `FREQ=MONTHLY;BYDAY=-1FR`（每月最后一个周五）。**必须同时给 `when`。**
- `remindBefore`：提前多少**分钟**发系统通知，例如 `15`。
- `onDue`：到点发给**你**（agent）的一句话，例如「总结昨天的提交」。这是让 agent 定时干活的入口。

### `item_list({ range? })`

`today` / `week`（默认）/ `all`。列出时间、重复规则、完成状态、**下次触发时间**。

### `item_update({ title, when?, note?, repeat?, done? })`

改一条。按**标题包含**找，只改你传的字段。`when` 传空字符串表示去掉时间。

### `item_remove({ title })`

删一条。除非用户明说删，否则优先用 `item_update({ done: true })`。

## 匹配规则（和旧版「待办」一致）

`item_update` / `item_remove` 按**标题包含**匹配（`title.includes(...)`），不是精确相等。命中多条时取**最近创建的那条**。找不到会报错——报错说明标题打错了。

## 完成是按「每一次」算的

「每周一 9 点的站会」标完成，**只标掉这一次**，下周一的还在。所以同一个标题的重复事项，这周做完了下周还是未完成，这是对的。

## 什么时候用

- 用户明确要求记住 / 提醒 / 安排某件事
- 用户提到具体的会议、截止时间、约会
- 用户问「我今天有什么事」「这周安排」
- 一件事需要拆成多步跟踪

## 边界（不要向用户承诺这些）

- **不会在应用关闭时触发。** 这是桌面应用，不是系统闹钟。应用没开时到点的触发会被记成「错过」，下次打开时列出来，**由用户决定要不要补跑**——不会自动补，也不会悄悄丢掉。
- **「让 agent 干活」需要应用窗口开着。** 到点时如果窗口没开，这次会记成「没送到」，同样是等用户决定。
- **不连外部日历。** 不读也不写系统日历、Google Calendar、CalDAV。
- 到点发的是**应用内 + 系统通知**，不是短信或邮件。
