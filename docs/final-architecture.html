§1

设计立场

三条原则,决定后面所有取舍。

宿主最小化。宿主只保留「元功能面板 + 内核 + 共享资源」。除模型设置与插件中心外,一切业务功能都是插件 —— 浏览器自动化、文件中心、待办、邮件、日历、知识库、ERP,包括未来的会议纪要与行政人事财务。没有特权插件。
  • 先自研后开放。当前全部插件第一方,但安全边界(独立进程、独立源、权限声明、CSP、授权确认)按未来开放生态的标准设计 —— 切换到第三方分发时架构零改动。
  • 对外一套接口。插件作者面对的是:一个 manifest、一个 HTML 面板、一个后端脚本。iframe 还是 WebContentsView 是宿主的实现细节,不出现在文档里。
  • 隔离从实测升格为合同。插件 UI 已实测独立进程(死循环 5 秒宿主响应 1–3ms);后续以 site-per-process 启动参数强制,堵死策略漂移。
§2

宿主边界

「资源 vs 功能」是唯一的分界线:面板 UI 是业务,归插件;单例共享资源是基础设施,归宿主、经权限门暴露。

层内容性质
宿主面板模型设置、插件中心仅有的两个宿主 UI,均为「配置应用本身」的元功能
宿主内核面板系统 / Rail / 能力枢纽 / pi-plugin:// 协议 / 市场 / 路由机制,不是功能
宿主资源文件系统访问、存储、通知、剪贴板、浏览器引擎经权限门暴露给插件的共享资源
其它一切浏览器自动化、文件中心、待办、邮件、日历、知识库、ERP…全部插件,可装卸、可被第三方替代

浏览器引擎为什么归宿主:它是单例资源 —— agent 工具、用户点击、pi-browser CLI 三方驱动同一实例、共享同一份持久登录态(persist 会话)。浏览器自动化插件使用它的方式与使用文件系统完全同构:声明 liveview 面板(挂载点)+ browser 权限(能力调用)。

§3

进程模型

每插件独立 UtilityProcess 后端 + 独立源沙箱 UI;双平面通信,主进程只做权限与握手。

主进程 PluginSystem │ Registry(扫描/engines 协商) CapabilityHub(权限门) Marketplace pi-plugin:// 协议 │ ├─ 控制平面(parentPort / IPC):生命周期 · 能力调用 · 工具执行 · 事件广播 ├─ 数据平面(MessagePort 点对点):面板 UI 事件直传,主进程只牵线不中继 │ ├─▶ 插件后端 ×N(UtilityProcess,独立进程,crash 自动重启 ×3) │ 工具实现 · 状态 · officecli 渲染管线 · filesystem/office/browser 能力调用 │ ├─▶ 插件 UI ×N(pi-plugin://<插件id>/ 唯一源沙箱 iframe,站点隔离实测生效) │ standard 面板(HTML + piSDK) │ └─▶ 浏览器引擎(宿主单例 BrowserView → 待迁 WebContentsView) liveview 面板 = 挂载点;bounds 槽位机制(0×0 上报 / reload 兜底已防御)

关键防御已内置:后端 crash 重启 ×3;file:// 渲染器秒开竞态(whenReady 门控 + 渲染器重试);数据面 outbox 缓冲(port 握手前事件不丢)。

常驻性与定时任务

插件 = 后端(UtilityProcess) + UI(面板) 后端:app 启动即拉起,永不因面板关闭而死 — 定时器/状态/调度逻辑的唯一归宿 UI :按需挂载;iframe 与 WebContentsView 同样随面板生命周期卸载,载体选择与常驻无关 定时任务(如日历每日 9 点提醒): 后端 setInterval 扫描 + storage 持久化 + 启动补跑(错过的触发一次性重放) 触发动作:notify.show(系统通知)· panel.setStatus(角标)· ui.render(面板刷新)· network.fetch 边界:app 关闭期间不执行(桌面应用物理边界,启动时补跑);UtilityProcess 独立进程,不受渲染器节流影响
定论:定时任务换不来 WebContentsView,WebContentsView 也带不来定时任务 —— 后端进程已经解决一切常驻需求;UI 载体只按「交互质量(standard iframe)vs 原生能力(liveview)」选择。
§4

对外接口(唯一一套)

插件作者的全部世界:一个声明文件 + 一个 HTML 页面 + 一个后端脚本。

manifest.json — 唯一声明入口

// 全部贡献点。panels 之外都是声明式注册,不构成"第二种 UI 写法"
{
  "id": "com.yourco.hr",
  "name": "人事系统",
  "permissions": ["network:hr.yourco.com", "storage", "filesystem"],
  "contributes": {
    "panels": [
      { "id": "main", "title": "人事", "entry": "./ui/index.html" },
      { "id": "web", "kind": "liveview", "title": "内嵌系统" }
    ],
    "tools": [ ... ],            // agent 工具(MCP inputSchema)
    "commands": [ ... ],          // 斜杠命令
    "selectionActions": [ ... ], // 滑词菜单动作
    "contextProviders": [ ... ], // 发送前上下文注入
    "settings": [ ... ],          // 插件中心自动设置表单
    "messageRenderers": [ ... ], // 对话内卡片(UiNode 声明式)
    "filePreview": [ ... ],       // 文件树点击路由认领
    "skills": [ ... ]             // agent 使用说明(可选)
  }
}

面板两种 kind

standard(默认,主接口)

写 HTML/CSS/JS 即可。宿主给独立沙箱源 + piSDK 全套:能力调用、后端消息、主题变量自动注入、选区自动进滑词、右键原生菜单、autoHeight。99% 的插件止步于此。

liveview(进阶,文档化)

需要原生级能力时声明:宿主为面板创建专属 WebContentsView,内容加载走 nativeview.* 能力(受同一权限模型约束)。适用:嵌第三方网页带独立会话、重 GPU、类浏览器体验。

声明式 UiNode 的定位:不作为面板接口,保留在消息卡片(对话内渲染工具结果 —— 数据驱动场景,声明式天然合适)。第一方插件的原声明式面板迁移至 HTML,顺带 dogfood 自己的 API。

后端契约(Node 子进程)

parentPort 收发五种消息:
  ready        → 握手(超时 10s)
  tool-call    → agent 调用工具 → 回 tool-result(content + 可选 card)
  ui-port      → 收 MessagePort,此后 UI 事件点对点直传
  call-result  → host.* 能力调用结果
  host-event   → 宿主推送(如 browser.urlChanged)
§5

权限与能力

一切宿主能力经 CapabilityHub 权限门;manifest 声明、安装时逐条授权确认。

能力权限说明
app.info—宿主/插件元信息
storage.*storage插件私有 KV(plugins-data/<id>)
notify.shownotify系统通知
panel.open / setStatus贡献面板即可focus 分级:no-focus-steal(后台动作只亮 badge)/ 自动展开(用户显式动作)
filesystem.readfilesystem文本读取(≤2MB)
filesystem.writefilesystem写回 + mtime 冲突检测(外部已改则拒写)
office.readfilesystemoffice 家族文本提取(供 agent 上下文)
browser.* ×9browsernavigate / back / forward / reload / getState / screenshot / click / getText / evaluate
network.fetchnetwork:<host>出站请求,域名 glob 白名单
nativeview.*liveview 声明原生视图内容驱动 待交付
agent.triggeragent插件主动触发 agent 对话(定时汇总、自动流程);带权限确认防滥用 待交付

协议文件服务(P9a 已交付)

  • pi-plugin://<id>/ws-file?path=<abs> — 工作区文件原始字节流;按 manifest 权限门控(无权限 403);HTTP Range/206(视频 seek、大文件流式)
  • pi-plugin://<id>/memory-file?name=<key> — 用户上传附件(主进程 LRU 注册表)

跨源隔离天然成立:别的插件读不到你的 pi-plugin:// 响应(无 CORS)。

§7

Office 高保真渲染

文件中心(com.pi.files)以 officecli 为渲染引擎 —— agent 写文档与用户看文档共用同一引擎,所见即 agent 所写。

  • 渲染管线:officecli view screenshot --page 1-50 → 单张全页 PNG(docx/pptx 全页、xlsx 活动表)→ 经 ws-file 协议给查看器 iframe → 缩放控件(25–400%/适应)
  • 保真度:真实 Office 排版管线 —— 纸张、页边距、分页边界、字体、形状、背景全部还原(pptx 实测像素级)
  • 性能:mtime 缓存(同文件秒开,LRU 24);写盘竞态防御(空内容延迟重读)
  • 引擎矩阵其余部分:Monaco(代码/文本编辑 + 写回)、pdf.js、docx-preview、Univer P9b 余项

§9

分发与路由

  • 市场:静态 index.json + zip + sha256 校验 + engines 版本协商 + 原子安装;卸载默认保留数据(重装恢复);授权确认对话框逐条列权限
  • 多根扫描:dev(开发)> user(市场安装)> builtin(内置);同名高优先级覆盖
  • filePreview 路由优先级:dev > user > builtin —— 第三方查看器装上即接管同扩展;无认领类型 → 系统默认应用打开(宿主永不渲染业务内容)
  • 连接器脚手架:examples/templates/connector-plugin/(对接真实 ERP/HR/财务系统的起点)
